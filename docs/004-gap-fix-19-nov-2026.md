# Penutupan celah hasil audit firmware dan server

## Konteks

Audit 19 Nov 2026 membandingkan tiga lapisan: sketsa lama `dump/sketch_nov18a/sketch_nov18a.ino`, firmware aktif `esp32/librasense_node/librasense_node.ino` versi 3.1.0, dan server Go di `internal/`. Tujuannya memisahkan celah yang bisa ditutup tanpa perangkat keras dari celah yang harus menunggu pengujian di board.

Sketsa lama tetap disimpan sebagai rujukan pin dan perilaku sensor, tetapi bukan firmware yang dipakai. Arsitekturnya bertentangan dengan 001: ambang, histeresis, dan keputusan aktuator berada di firmware, panel tertanam di firmware, dan relay dipisah dari kipas.

## Rencana kerja

1. Kompilasi firmware memakai arduino-cli dan core `esp32:esp32` yang sudah terpasang di mesin ini.
2. Tambah backoff pada `pushReadings()` tanpa mengubah kontrak request dan response.
3. Tambah pemangkasan riwayat dan penolakan duplikat `ts` di `internal/store/store.go`, lalu panggil dari `internal/httpapi/device.go`.
4. Tambah test untuk duplikat dan retensi.
5. Tandai sketsa lama di 002 dan dokumen ini sebagai rujukan saja, tanpa mengubah isi `dump/`.
6. Perbaiki 002 agar cocok dengan kode, lalu isi hasil verifikasi di dokumen ini.
7. Jalankan `gofmt -w .`, `go vet ./...`, `go test ./...`, `go build ./cmd/librasense`.

## Perubahan yang dikerjakan

- `esp32/librasense_node/librasense_node.ino`: penghitung gagal kirim dan jeda backoff 0, 5, 10, 20, 40, 60 detik. Pembacaan sensor dan LCD tetap berjalan pada interval normal. Backoff kembali nol setelah satu kiriman sukses.
- `esp32/librasense_node/librasense_node.ino`: sensor gagal ditampilkan sebagai `--` di LCD, bukan `nan` atau angka basi.
- `internal/store/store.go`: `ReadingExists` dan pemangkasan otomatis 5000 baris terakhir per perangkat, dijalankan di dalam transaksi `SaveReading`.
- `internal/httpapi/device.go`: kiriman dengan `ts` perangkat dilewati bila kombinasi perangkat dan `ts` sudah ada. State dan perintah tetap dikirim balik. Jalur waktu server tidak berubah.
- `internal/store/store_test.go`: test `ReadingExists` dan retensi.
- `internal/httpapi/app_test.go`: test `TestDuplicateDeviceTimestampIgnored`.
- `docs/002-firmware-push-19-nov-2026.md`: tabel pin, versi firmware, dan bagian Verifikasi disesuaikan dengan kode.

## Verifikasi

Kompilasi firmware dijalankan di mesin pengembang, bukan di VPS:

```
arduino-cli compile --fqbn esp32:esp32:esp32 esp32/librasense_node
```

Hasil setelah perubahan: berhasil, sketch 1095688 byte (83 persen dari 1310720), variabel global 50616 byte (15 persen dari 327680). arduino-cli 1.6.0, core esp32 3.3.11, library DHT sensor 1.4.7. Unggah ke board dan pengukuran aktuator belum dilakukan.

Server:

```
gofmt -w .
go vet ./...
go test ./...
go build ./cmd/librasense
```

Hasil: `go vet` bersih, `go test` lulus untuk `internal/httpapi` (0,36 detik) dan `internal/store` (1,01 detik), build menghasilkan binary tanpa error.

## Terbuka

- Unggah firmware ke board, cek polaritas relay, dan ukur kebisingan ruangan untuk `bs`.
- `TLS_INSECURE` masih aktif sampai sertifikat Cloudflare dipin atau CA bundle dipasang.
- Watchdog dan pengujian perilaku perangkat saat server mati lebih dari satu jam.
- Panel belum menyembunyikan pengaturan rak 3 untuk konfigurasi 2 rak.

## Catatan lanjutan

Kebutuhan berubah menjadi 3 rak setelah dokumen ini selesai. `RACK_COUNT` dinaikkan menjadi 3 dan pin rak 3 diaktifkan di 005. Angka ukuran firmware di atas berlaku untuk keadaan saat dokumen ini ditulis.
