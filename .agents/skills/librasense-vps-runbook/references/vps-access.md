# VPS Access Baseline for LibraSense

Shared host baseline verified on 12 November 2026 from the MedVault runbook and
on 19 November 2026 with `deploy/check-vps.sh`. LibraSense was provisioned and
deployed the same day.

---

## 1. Accounts

| Role | Account | Notes |
| :--- | :--- | :--- |
| Bootstrap admin | `liteclaw` | Key based SSH, full sudo. Provisioning used this. |
| Bootstrap console | `ubuntu` | Full sudo. Used for the 19 Nov 2026 preflight. |
| Service account | `librasense` | uid 1005, password locked, scoped sudo, owns the container and data. Provisioned 19 Nov 2026. |
| Other tenant | `medvault` | Ports 8095 and 8096. Do not disturb. |

`vps-lama` reaches `liteclaw`. `ubuntu@<VPS_IP>` refuses the workstation
key, so `liteclaw` is the bootstrap path.

`deploy/setup-user.sh` creates `librasense`. Idempotent.

## 5. Filesystem

```text
/home/librasense/
|-- .ssh/authorized_keys        mode 0600
|-- .env                        mode 0600
|-- bin/                        mode 0750
|-- backups/                    mode 0750
`-- data/                       mode 0700, owner 10001:10001
```

`data/` is the container bind mount. Owner is numeric because the container
runs as uid 10001.

## 6. Verification Command Set

Safe commands as the bootstrap admin, no sudo required:

```bash
id
uname -a
free -m
swapon --show
df -h /
podman --version
systemctl --version | head -n 1
ss -ltn
systemctl is-active cloudflared-claw.service
systemctl is-enabled cloudflared-claw.service
```

After provisioning and deploy, as the service account:

```bash
systemctl is-active librasense.service
sudo podman ps -a
sudo podman stats --no-stream
sudo journalctl -u librasense.service -n 100 --no-pager
curl -fsS http://127.0.0.1:8097/health
```

`podman ps` must be called without arguments on this host. `sudo` is required
for every podman command.

| Metrics | `127.0.0.1:0`, disabled |

Ingress lives in the Zero Trust dashboard. LibraSense has two public hostnames,
both to `http://127.0.0.1:8097`:

- `librasense.<domain>` with its own Access application, AUD
  generated by Cloudflare Access.
- `iot.<domain>` with no Access application, guarded by `DEVICE_TOKEN`.

Team domain is `<team>.cloudflareaccess.com`.

The tunnel is shared with MedVault. Leave its unit and MedVault hostnames alone.
